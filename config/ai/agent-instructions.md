# Commit messages

- コミットメッセージはできるだけ詳しく書く。
- コミットメッセージの言語は、対象リポジトリの直近のコミット履歴を確認し、主に使われている言語に合わせる。履歴が混在する場合は直近の傾向を優先し、判断できない場合はユーザーに確認する。
- コードから読み取れる変更内容の羅列より、コードから読み取れない背景を優先して記載する。
- なぜこの変更が必要になったのかを書く。
- プルリクエストを作成するに至った理由を書く。
- 関連する Issue、PR、バグ報告、設計上の制約があれば含める。
- 代替案や採用しなかった案があれば簡潔に書く。
- 1行目は要約にする。本文には背景、理由、注意点を書く。
